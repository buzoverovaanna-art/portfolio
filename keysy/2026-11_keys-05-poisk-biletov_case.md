# Кейс 05. Агент, который ищет дешёвые билеты

**Отрасль:** личная автоматизация / тревел
**Период:** 2026
**Роль:** проектирование агентной системы
**Стоимость:** свой проект

## Задача

Регулярно проверять цены на авиабилеты по нужным направлениям и не пропускать дешёвые варианты.
Ручная проверка съедает время и всё равно нерегулярная.

## Что было до

Цены смотрелись вручную, когда вспомнишь. История цен не сохранялась,
сравнить «сейчас дешевле, чем месяц назад» было нельзя.

## Что сделала

1. Собрала систему из двух агентов: один ищет билеты из конкретного города, второй сравнивает с прошлыми проверками.
2. Подключила API поиска билетов, задала потолок цены — всё дороже отсекается.
3. Настроила накопление истории цен в таблицу, чтобы видеть динамику, а не один снимок.
4. Сделала итоговый дайджест в виде веб-страницы: что уложилось в потолок, где подешевело.
5. Жёстко ограничила: система только показывает варианты. Бронирования и оплаты нет.

**Инструменты:** Claude Code, субагенты, Travelpayouts API, CSV-история, HTML-дайджест.

## Результат

Проверка цен занимает минуты и не зависит от того, вспомнил человек или нет.
Видно не только «есть ли дешёвый билет», но и как цена менялась.
Решение о покупке остаётся за человеком, платёжные данные нигде не вводятся.

## Чему научилась

Автоматизация должна заканчиваться там, где начинается ответственность человека.
Показать варианты — можно. Решать за человека — нельзя.
